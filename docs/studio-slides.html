The problem

Five windows for one job

Window 1

SQL client

Write and run SQL against SingleStore. Knows the syntax, not your schema.

Window 2

Notebook

Python for the analysis, a copy of the data pulled across for each try.

Window 3

Pipeline and cluster consoles

Loads from Kafka and S3, node health, slow queries. Each in its own tool.

Window 4

SAS Studio

The SAS side of the same data: libraries, caslibs, PROC SQL, FedSQL.

Window 5

The AI chat

Helpful, but blind: it never sees your tables, and you paste its answer somewhere else.

The cost. Context is lost at every switch. The assistant guesses column names, the notebook copies data that should stay in the database, and nobody sees the whole picture.
Ask the room how many windows they have open for a normal day with SpeedyStore and Viya. Five is a conservative count.
The idea

One workspace, with the assistant inside it

Three things to point at: the rail on the left, the assistant panel inside the window, and the two systems on the right. MCP is how one assistant reaches both, with tools that are read-only by default.
Write and run

A SQL editor that knows your schema and your SAS

SingleStore

SQL with the schema at hand

  • Autocomplete for SingleStore SQL, built-in functions with signatures, your databases, tables, columns and procedures
  • Ctrl+Enter runs the statement under the cursor; Run all runs a whole script and gives each statement its own result tab
  • Reads run at once; statements that change data or schema ask first
  • Results grid, sorting and CSV export, a chart from the result, run history, tabs with their own database and file
SAS Viya

The same SQL, through SAS

  • Run as picks the language: SingleStore SQL, PROC SQL, FedSQL or FedSQL in CAS, with the matching tree of databases, libraries or caslibs
  • Result, the SAS log and a Pushdown tab that shows what SAS handed to SingleStore
  • Open and save .sql and .sas files on this computer, in SAS Content or on the SAS server, with a version check so nobody's work is overwritten
  • Long runs go to the background with a Stop button
Try it both ways. The same query native in SingleStore and through SAS side by side, with the pushdown visible. That is the SpeedyStore conversation in one tab.
The pushdown tab is the demo moment for SAS people: they see which part of their PROC SQL SingleStore executed.
Explore and analyse

A notebook where the data stays in the database

SQL cells

Run against SingleStore; the result becomes a pandas DataFrame in the next cell. %sql and %%sql magics for the Python crowd.

Python cells

A Jupyter kernel in its own environment with a Packages panel. Charts inline. The notebook file is a normal .ipynb, compatible with SingleStore Notebooks.

SAS cells

Run in a SAS Compute session on Viya. Each session gets the library S2 on the notebook's database, so a DATA step reads and writes SingleStore directly through SAS/ACCESS.

Several notebooks as tabs

Each with its own kernel, database and file. Save to this computer, SAS Content or the SAS server.

Claude in the side panel

Ask for the next cell in plain words. It reads the schema, writes SQL or Python, and you insert it with one click.

The point for SAS Viya: the data never leaves the database for a local copy. SAS reads SingleStore itself through the S2 library, and CAS pushes queries down.
The assistant

Claude helps where you work, and you stay in control

It sees what you see

The chat panel in the SQL editor and the notebook reads the schema and runs read-only queries before it answers, so the SQL it writes uses your real table and column names.

It suggests, you run

Answers come as SQL, Python or SAS code with an insert button. The assistant has no write access, no shell and no files. Nothing changes in the database until you run it.

It knows SingleStore

Every question carries a SingleStore SQL skill with the pitfalls learned on real clusters: case-sensitive names, procedure syntax, shard and sort keys. You add to it as you learn.

Three speeds

Fast, Balanced or Thorough, picked per question. Each editor keeps one assistant running, so follow-ups are quick and keep the conversation.

Ask Claude everywhere

The Schema Explorer and Pipeline Monitor hand a table, a skew finding or a pipeline error to the chat with the context already filled in.

This is the takeaway slide for "AI belongs where you work". The assistant runs through your own Claude login, with no API key, and it is read-only by design.

SAS Viya built in

SAS is a source, a language and a file system in the Studio

Sources

SAS libraries and caslibs

The Schema Explorer and the SQL editor's tree list SAS libraries from the Compute session and caslibs from CAS, next to SingleStore databases. Badges tell the kind apart: a SpeedyStore caslib that pushes down live, a standard connector that loads into memory, a SAS/ACCESS libname, a SAS 9 library over SAS/CONNECT.

Languages

PROC SQL, FedSQL, CAS

Run as picks the engine per tab. SAS cells in the notebook. One Compute and one CAS session per Viya connection, started in the background when the Studio opens so the first run doesn't wait.

Files and sign-in

SAS Content and SAS server

Open and save programs and notebooks where SAS Studio keeps them. Sign in with your own Viya account through SAS Logon; several saved Viya connections, one active, a tab can be pinned to another.

Why it matters. SAS SpeedyStore is SAS Viya and SingleStore together. The Studio shows both sides of every table and lets you choose, per query, where the work runs.
The badges on caslibs are a good teaching moment: SS means CAS pushes the query down to SingleStore live; S2 means the standard connector copies the table into memory.

How you run it

Inside Claude, or on its own

With Claude

An MCP server with apps

  • Runs from Claude Code, Claude Desktop or VS Code; the Studio opens in the chat or full-window in the browser
  • Slash commands for the workspace, a notebook, pipeline health and a table report
  • Claude can also use the tools directly: run SQL, create and start pipelines, describe tables
  • Restart the server in seconds after a code change, without reconnecting
Without Claude

A desktop app

  • The same views in their own window from a desktop shortcut; one-command install on Windows
  • Talks directly to SingleStore and SAS Viya; no Claude subscription or MCP client needed
  • Only the chat panels need Claude; everything else works
  • Other MCP clients get the tools with plain text results

Any SingleStore

Self-managed clusters and Helios alike. Passwords in the OS credential store; Entra ID and SSO sign-in supported.

Official SDKs

The MCP Python SDK, SingleStore's own Python client and the MCP Apps browser client. The project itself is glue.

Open source

github.com/jonasliesas/singlestore-mcp-server, tests on every push. Version 0.10 added SAS.

Say plainly that this is a pre-sales build on an open-source server, not a SAS product. Then show the shortcut: double-click, the Studio opens.
